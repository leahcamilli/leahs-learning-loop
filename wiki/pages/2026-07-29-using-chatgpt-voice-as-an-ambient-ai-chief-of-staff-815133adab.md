## TL;DR

> Use ChatGPT Voice as a coordination layer: ask it to review project status and recommend next steps, then delegate approved work into separate threads. This can reduce context switching while keeping sensitive approvals and final judgment with the human.

## Key Takeaways

1. Treat voice as an orchestration interface for inspecting context and routing work, not merely as speech-to-text.
2. Ask for a status summary and one concrete next action per active project before approving any execution.
3. Keep the main voice conversation focused on coordination by spinning up a separate thread for each approved task.
4. Create a compass doc for each project with its short-term goals, long-term goals, blockers, and definition of done.
5. Use three recurring checkpoints: a morning kickoff, stream-of-consciousness capture during the day, and an end-of-day review of work that could continue overnight.
6. Ask what should happen next, what might be missing, and what blockers exist instead of prescribing every step yourself.
7. The presenter recommends one always-on headquarters computer controlled from other devices, while leaving visible consent steps and final decisions to the human.

## Overview

This lesson explains a workflow from the source video in which ChatGPT Voice is used less like dictation and more like an always-available coordinator for other AI tasks. The presenter argues that voice becomes useful when it can inspect project context, start separate threads for work, and control a main computer from other devices. The practical takeaway is not the hype, but the operating pattern: ask for status, ask what to do next, then delegate execution to separate threads. Because the source is a single transcripted demo, treat specific product claims as reported behavior from the presenter, not independently verified documentation.

## Key Concepts

- **Ambient AI**: The source uses this term for an AI that is continuously available, can be consulted from anywhere, and reduces friction between having an idea and turning it into action.
- **Voice as orchestration, not dictation**: The lesson distinguishes simple speech-to-text prompting from a voice interface that can inspect context, coordinate work, and trigger separate task threads.
- **Chief-of-staff model**: The presenter recommends treating the voice agent as a coordinator that routes work to other agents or chats instead of doing every task directly in the main voice conversation.
- **Thread delegation**: A repeated tactic in the source is to ask for a next step, then say 'spin up a thread' for each approved action so work is isolated by project or task.
- **Compass docs**: The source recommends creating markdown files that state short-term and long-term project goals so agents can recommend actions against explicit objectives.
- **Headquarters device**: The presenter suggests choosing one always-on computer as the main execution node and letting mobile devices issue voice commands that operate through that machine.

## How It Works

Start by treating the voice interface as a control layer over your projects rather than a place to type with your mouth. In the source workflow, the first move is a status review: ask for updates across active projects and request one recommended next step for each. After hearing the recommendations, approve only the useful ones and explicitly delegate them into separate threads. This keeps the voice conversation focused on coordination while execution happens elsewhere.

A practical pattern from the source is: morning kickoff, stream-of-consciousness capture, and end-of-day debrief. In a morning kickoff, ask for current project status and one concrete next action per project. During a walk or commute, dump ideas, constraints, and goals out loud, then ask what should be built or advanced based on that discussion. At the end of the day, ask what work could continue overnight, then spin up threads for those tasks.

The source also emphasizes asking more questions than commands. Instead of specifying every step yourself, ask what the system thinks should happen next, how it would approach the goal, or what blockers it sees. This reduces cognitive load and can surface options you had not considered. To improve answer quality, create a 'compass doc' for each project that records its short-term and long-term goals. That gives future recommendations a stable reference point.

Operationally, the presenter recommends one main computer as headquarters and other devices as remote control points. In the transcript, mobile voice sessions are described as controlling the main machine, while some approvals still require the human to complete visible consent steps. That implies a useful boundary for your own workflow: let voice handle coordination and preparation, but expect sensitive approvals and final judgment to remain human tasks.

## Training Exercise

Pick one real project and create a short compass doc with: current goal, long-term goal, active blockers, and what 'done' looks like this week. Then run a three-step drill: 1. Ask for a status summary and one next step. 2. Ask what you may be missing or what should happen next. 3. Approve only one action and restate it as a delegated thread. Afterward, review whether the voice session helped you decide faster, reduced context switching, or exposed missing information. Record the result in your knowledge base as a reusable workflow note.
